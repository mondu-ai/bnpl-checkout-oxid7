## Project Overview

OXID eShop 7.x payment module integrating Mondu BNPL (Buy Now, Pay Later). Module ID: `oemondu`. PSR-4 namespace: `OxidEsales\MonduPayment\`. Composer type: `oxideshop-module`.

Three payment methods: Invoice (`oxmondu_invoice`), SEPA Direct Debit (`oxmondu_direct_debit`), Installment (`oxmondu_installment`).

## Installation (in OXID shop context)

```bash
# From shop root
vendor/bin/oe-console oe:module:install-configuration source/modules/mondu/bnpl-checkout-oxid
composer config repositories.mondu/bnpl-checkout-oxid7 path source/modules/mondu/bnpl-checkout-oxid
composer require mondu/bnpl-checkout-oxid7
```

Module is activated/deactivated via OXID admin: Extensions → Modules → Mondu.

## No Build/Test/Lint Tools

This project has no test suite, no linter, no CI/CD pipeline, and no build step. There is no `phpunit.xml`, `phpcs.xml`, `phpstan.neon`, Makefile, or GitHub Actions configuration.

## Architecture

### OXID Module Extension Pattern

The module uses OXID's `metadata.php` class extension chain (`extend` array). Extended classes inherit from a virtual `*_parent` class generated by OXID's module system — never from the OXID class directly:

- `PaymentGateway extends PaymentGateway_parent` — not `\OxidEsales\Eshop\...\PaymentGateway`
- Always call `parent::method()` to preserve the extension chain

### Key Layers

**Controllers** — two types:
- **Extended controllers** (`Controller/PaymentController.php`, `Controller/OrderController.php`, `Controller/Admin/*`) extend OXID's controllers via `*_parent` classes. They intercept OXID flows (payment list filtering, order execution, admin shipping/cancellation).
- **Standalone controllers** registered in `metadata.php` → `controllers` array: `MonduCheckoutController` (`cl=oemonducheckout`), `MonduWebhooksController` (`cl=oemonduwebhooks`), `CancelController`, `DeclinedController`.

**Core/Http/MonduClient** — single API client for all Mondu REST API v1 calls. Sends `Api-Token`, `x-plugin-name`, `x-plugin-version` headers. All API errors are caught as `InvalidRequestException` and logged via `logEvent`.

**Core/Mappers** — transform OXID basket/order data into Mondu API payloads: `MonduOrderMapper`, `MonduInvoiceMapper`, `MonduAdjustmentMapper`.

**Core/PaymentHandler** — strategy pattern per payment method (`MonduInvoiceHandler`, `MonduDirectDebitHandler`, `MonduInstallmentHandler`), dispatched by `PaymentGateway::createPaymentHandler()`. Each handler stores the Mondu order after successful payment execution.

**Core/OrderShippingProcessor** — creates Mondu invoices when orders are shipped from admin; cancels invoices on order reset.

**Core/OrderAdjustmentProcessor** — sends order adjustments to Mondu API when order articles change.

**Core/WebhookHandler/WebhookHandler** — processes incoming webhooks by topic (`order/*`, `invoice/*`). Signature verification uses HMAC-SHA256 with per-shop webhook secret.

### Database Tables (created on activation)

- `oemondu_orders` — links OXID orders to Mondu order UUIDs and states. FK → `oxorder`.
- `oemondu_invoices` — links invoices to Mondu invoice UUIDs. FK → `oemondu_orders`.

### Configuration

Module settings defined in `metadata.php` → `settings`: `oemonduApiKey`, `oemonduSandboxMode`, `oemonduErrorLogging`, `oemonduWebhookSecret`, `oemonduIsMerchantIdentified`.

Accessed via `Settings/Service/ModuleSettingsService` (DI-registered in `Settings/services.yaml`) and `Core/Config`.

### DI Services

Root `services.yaml` imports `Settings/services.yaml`. Registered public services:
- `MonduClient`
- `BuyerFeeCentsServiceInterface` → `BuyerFeeCentsService`
- `ModuleSettingsServiceInterface` → `ModuleSettingsService`

Most classes are instantiated via `oxNew()` (OXID's factory), not DI.

### Checkout Flow

1. Customer selects Mondu payment → `PaymentController::getPaymentList()` filters methods by Mondu API availability
2. On order confirmation → JS calls `MonduCheckoutController::createOrder()` which maps basket data and creates a Mondu order via API
3. Mondu widget opens → on success, redirects to `OrderController::execute()` with `order_uuid`
4. `OrderController::monduExecute()` finalizes the OXID order, then confirms it with Mondu API
5. `PaymentGateway::executePayment()` dispatches to the appropriate payment handler, which stores the Mondu order locally

### Frontend

Twig templates in `views/twig/extensions/themes/`. JS in `out/src/js/` (`mondu_checkout.js` handles widget init, `http_request.js` for AJAX). Translations: DE, EN, NL in `translations/` (storefront) and `views/admin_twig/` (admin).

### API Environments

Configured in `Core/Config`: production (`api.mondu.ai`), sandbox (`api.demo.mondu.ai`), local (`localhost:3000`). Sandbox mode toggled via module settings.
